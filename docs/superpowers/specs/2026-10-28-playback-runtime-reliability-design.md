# 播放与运行时可靠性修复设计

## 目标

修复播放主链路中的重复解析、旧播放器残留、续播错误、错误不可恢复等问题，并同步修复搜索、分页、下载、更新、观看历史和详情页的已知运行时缺陷。修复完成后，应用明确只将 m3u8 剧集作为在线播放资源，并且播放流程、错误状态和下载状态都必须可取消、可重试、可恢复。

## 产品边界

- 在线播放剧集仅支持 m3u8/HLS。
- MP4、FLV、网页播放器和未知直链不进入选集列表。
- README 必须明确写明“当前在线播放仅支持 HLS / m3u8”，不能再宣称支持 MP4。
- 已存在的本地下载记录仍可打开；本次不扩展新的在线媒体格式能力。
- 不重做页面视觉设计，不改变现有品牌色、间距、卡片布局和底部导航。

## 架构

采用“播放协调器 + 定点修复”的方案。将播放请求的取消、代次校验、旧播放器暂停和进度恢复提取为可单独测试的协调逻辑；播放器页面只负责连接 Expo 播放器、界面和协调器。其他模块通过小型纯函数、请求序号和服务层错误传播修复，不做无关重构。

### 播放数据流

1. 页面读取设置；读取失败时使用默认设置并继续，而不是永久停在未加载状态。
2. 每次 URL、线路或重试开始前创建新的请求代次，并先暂停旧播放器。
3. 播放地址解析接受 `AbortSignal`，超时、页面跳转或新请求会取消旧请求。
4. 只有当前代次可以写入解析结果、替换播放器、恢复进度和写入历史。
5. `replaceAsync` 成功后等待 `sourceLoad` 或已就绪状态，再判断续播位置是否有效。
6. 如果旧进度距离结尾不超过 10 秒、超过视频时长或时长无效，则不恢复该进度。
7. 播放期间按真实 `bufferedPosition` 显示缓冲状态；解析阶段使用不确定进度动画，不再伪造百分比。
8. 每两秒保存一次进度，并在切集、重试、返回和页面卸载时强制 flush。
9. 自动下一集始终自动播放；手动上一集/下一集也始终自动播放；“进入播放页自动播放”只控制普通首次进入。

### 播放错误与导航

- 播放页必须提供屏幕内返回按钮。
- 解析失败和播放器失败区域必须提供“重试”按钮，点击后重新开始当前剧集。
- 新请求开始时清空上一次错误去重状态，因此同一错误再次出现仍会提示。
- 播放页详情请求必须支持取消，并依赖 `vodId`、`siteUrl` 和 `detailUrl`。
- 线路匹配使用 `sourceIndex`，不再只依赖剧集名和线路名。

## 模块设计

### 播放协调

新增一个无 React Native 依赖的播放协调器，接收播放器适配器、解析函数、进度存储和当前剧集信息。协调器负责：

- 生成并校验请求代次。
- 取消旧解析和旧恢复流程。
- 在开始新请求前调用播放器 `pause`。
- 只在最新请求成功时调用 `replaceAsync`。
- 对过期结果执行空操作。
- 提供 `dispose`，用于卸载时取消任务并强制保存进度。

播放器页面通过适配器把 Expo `VideoPlayer` 的 `pause`、`replaceAsync`、状态和时长接入协调器。协调器不直接引用 React 或 Expo，从而可以用单元测试验证竞态。

### 进度恢复与保存

新增纯函数：

- `shouldRestorePlaybackProgress(positionSeconds, durationSeconds)`：仅在位置大于 3 秒、时长有效、位置小于时长减 10 秒时返回 true。
- `normalizePlaybackProgress(positionSeconds, durationSeconds)`：把毫秒与秒数限制在有效范围内。
- `buildBufferOptions(platform)`：使用适中的缓冲配置，Android 前向缓冲 30 秒、最小启动缓冲 2 秒、最大 64MB；iOS 使用系统自适应前向缓冲。

播放器保存两类数据：

- `app_settings` 中的 `player.progress.<url>` 继续作为续播兼容数据。
- `watch_history.positionMillis` 和 `durationMillis` 同步更新，避免历史表长期为零。

观看历史新增按记录 ID 更新进度的数据库接口。Context 暴露 `updateWatchHistoryProgress`，更新后只替换对应内存记录，不在每次播放进度 tick 时重新加载全部用户数据。

### 请求竞态

首页、分类、普通搜索和播放页各持有递增请求序号。异步响应只有在序号仍为最新值时才允许写入页面状态。首页页码只在请求成功后推进，失败时不跳过下一页。

服务层区分“成功但无结果”和“网络/HTTP/JSON 失败”：

- 搜索、分类和详情请求失败时抛出带可读消息的错误。
- 页面在 `catch` 中显示网络错误。
- 聚合搜索分别统计成功站点、失败站点和结果数；全部失败时显示网络错误。

### 下载

- 普通文件目标名包含下载任务 ID，避免同一影片同一集重复下载互相覆盖。
- 下载记录分组键包含站点或详情地址，避免不同站点同名影片被合并。
- 普通文件开始下载前执行可取消的 HEAD 探测；明确返回 4xx/5xx 或 HTML 时拒绝创建任务，405/501 等不支持 HEAD 的服务器允许继续。
- HLS 并发 worker 共享失败状态和 `AbortController`。任一分片失败后停止领取新分片并取消其他分片请求，使用 `allSettled` 等所有 worker 结束后再统一写入错误状态。

### 更新

- 自动更新检查和安装入口只在 Android 执行。
- 强制更新按钮关闭说明弹窗并显示下载进度，不再让弹窗永久阻塞错误处理。
- APK 下载后校验文件非空；如果版本接口提供 `md5`，使用文件摘要校验；如果提供 `size`，校验字节数。生产接口未提供摘要时仍依赖 Android 包管理器的同包名、同签名安装校验，但应用层至少校验 HTTPS、非空文件和可选摘要。
- 失败后恢复可重试状态。

### 观看历史

- 有站点和影片 ID 时，历史 ID 使用 `siteUrl::vodId::sourceName::episodeName::URL(去掉 query/hash)`。
- 无影片 ID 的本地记录继续使用本地 URI。
- 同一集地址只改变临时 token 时不再生成新历史记录。

### 详情页

- 缺少 `id` 或站点地址时立即退出加载状态并显示参数错误。
- 详情请求使用取消标记，避免旧请求覆盖新请求。
- 请求失败时显示可重试的错误态，而不是永久骨架屏。

## 可访问性与交互

- 播放页返回、重试、收藏和下载按钮提供 `accessibilityLabel`。
- 错误态和加载态不能依赖颜色单独表达。
- 返回与重试按钮保持至少 44x44 的触控区域。

## 测试策略

项目原先只有骨架覆盖脚本，没有业务测试。新增 Vitest 作为开发依赖，使用纯函数和注入式协调器测试运行时行为，避免依赖原生模拟器完成单元验证。

必须新增并先看到失败的测试：

- `parseEpisodes` 只保留 m3u8，并保留线路与集数信息。
- 播放协调器在新请求开始时暂停旧播放器。
- 较旧的解析结果完成后不能替换新请求的视频源。
- 取消后的解析结果不能写入历史或恢复进度。
- 接近结尾的进度不恢复。
- 当前进度 flush 后写入 app settings 和 watch history。
- 自动下一集即使关闭“进入播放页自动播放”仍会播放。
- 首页加载更多失败后不推进页码。
- 较旧的搜索响应不能覆盖新搜索。
- 聚合搜索全部站点失败时显示网络错误。
- 下载文件名包含任务 ID，不同站点同名影片分组不冲突。
- HLS worker 失败后不再领取新分片。
- 稳定历史 ID 忽略 query/hash 中的临时 token。
- 强制更新弹窗可关闭并恢复错误状态。

页面级竞态通过把决策提取为纯函数或协调器来测试；播放器与 Expo 原生播放器的最终集成通过 TypeScript、Android 构建和手工冒烟流程验证。

## 错误处理

- 所有网络请求具有超时和取消能力。
- 用户可见错误使用中文，不直接展示 `TypeError` 或技术堆栈。
- 取消属于受控状态，不显示错误弹窗，也不写入失败记录。
- 页面卸载后禁止调用状态更新、历史写入和播放器操作。

## 验收标准

- 非 m3u8 剧集不展示，README 明确说明仅支持 HLS/m3u8。
- 正常进入播放页时每个剧集地址只解析一次，即使详情稍后返回。
- 切集、重试、返回后不会继续播放上一集声音。
- 播放失败时用户可以重试和返回。
- 缓冲百分比不再按时间伪造，续播不会跨越视频结尾。
- 首页、分类和搜索不会出现旧结果覆盖新结果；加载更多失败不跳页。
- 全部站点失败时聚合搜索显示失败状态。
- 重复下载不会覆盖同名文件，不同站点同名影片不会合并下载文件夹。
- 强制更新失败后界面仍可操作。
- 观看历史进度和时长能够更新，临时 URL token 不产生重复记录。
- `npm test`、`npx tsc --noEmit`、`npm run test:skeleton` 全部通过。
- Android release 构建成功。

## 非目标

- 不恢复 MP4 在线播放。
- 不增加 DRM、字幕、倍速或新的播放器 UI。
- 不实现跨设备云同步。
- 不重写 SQLite 数据层。
